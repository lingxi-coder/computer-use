# ADR-0002：同步状态机与进程外壳（本阶段不引入异步运行时）

- 状态：已采纳，已实现（M1 阶段 S3–S5）。**偏离** M1 计划的 D4 中“进程外壳用 tokio”的设想。
- 相关章节：主设计 §11.2、§20.1；计划决定 D4

## 背景

接纳协议要求“额度占用 + active attempt + 决策消费 + 唯一映射 + outbox”在一个持久提交点完成（§11.2），并且根取消必须先在内存关闭准入、再持久化。测试需要确定性：虚拟时间、可复现的事件顺序、故障注入点。同时本机磁盘紧张，依赖树越小越好。

## 决定

1. `ExecutionCore` 与 `Engine` 都是**同步、无 IO 的状态机**：事件进、效果出，时间是参数。`Engine::handle(now_ms, Input) -> Vec<Output>` 一次处理有界工作（`MAX_ROUNDS`）后返回；需要回答的请求是输出，答案作为之后的输入回来。
2. **存储**：一个 SQLite 连接、WAL、FULL 同步；各模块只写自己的表，跨 owner 的操作通过窄端口（`DecisionLedger`）在**调用方的同一个事务**里完成。单事务接纳有三个注入点（任务写之后、Reaction 写之后、提交之前）。
3. **进程外壳**用标准库：每个进程一个单线程事件循环，每条流一个读线程，循环用 `recv_timeout` 等待核心的下一个期限。没有异步运行时。
4. 时间由外壳从共享时钟读取并传入；引擎与核心从不读时钟。

## 后果

- 好处：测试完全确定（进程内世界由测试推进时间）；接纳的原子性不依赖 await 点；编译与磁盘成本低；跨进程测试（真实二进制）约 1.6 秒跑完 8 项。
- 代价：握手在接受线程里阻塞（有 5 秒上限）；每个流一个线程在流很多时不划算。独立审查修复后 device 的 host/supervisor 输出、M2 source 输出使用独立有界 writer：控制线程非阻塞入队，溢出或 worker 故障关闭门/连接，正常退出只限时等待输出。阻塞 IO 不再运行在停止与期限控制循环中。
- 重新评估的条件：M2 引入感知 worker 与帧通道、或 S2 的网络调用需要并发 IO 时，再决定用线程池还是异步运行时。状态机本身不需要改变。

M2 原生 AX 提交使用 Pending/completion 窄端口：Core 保持同步、时间由外壳传入，AX worker 与有界管道独立运行，停止不等待回执。没有引入 tokio，详见[生产原生后端](m2-native-device-pipeline.md)。
