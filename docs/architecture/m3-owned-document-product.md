# Temporary TextEdit document in the product

The product entry creates a new empty document through Main's trusted owned
launcher. It does not accept a path, process ID, registration, initial body or
helper selection from the renderer. Main retains the opaque registration and
the launcher that owns the exact new TextEdit instance and private directory.

Owned Source deliberately keeps generic completeness and window target
selection unavailable. Document editing therefore uses a separate permission
for this precise Main-created document, rather than manufacturing a generic
observed window. Editing and saving each have a Cancel-by-default native
confirmation. Editing does not grant Save. Task confirmation and Execute mode
remain separate. The console remains visible while an owned task has no generic
window target, so the product does not hide its Stop control behind an absent
indicator position.

Production planning requires a configured model with explicit S2 purpose
authorization. The existing owned-reference route remains a diagnostic route;
the product document entry never enables it as a fallback. A saved model key
does not restore purpose, document-editing or Save permission.

The renderer sees phase, availability flags and a bounded reason. It cannot
grant input, decide file lineage, install a new registration or conclude a
task. The private retained-Root revisit still requires Engine's settled Save,
the earlier CurrentUi effect, Main's fixed file version and a new Source
session's exact readback. Reopening clears editing and Save permission and adds
no new input.

Main fences pending document operations by generation and cancels native
permission sheets on Stop, revoke, model change and quit. Unknown cleanup
remains unknown across process replacement. Shutdown targets only the
launcher-owned process and file; unconfirmed cleanup cannot be reported as
successful removal.

This uses an ephemeral dummy route only to verify S2 purpose consent, without
calling a provider or running a model-planned task. Two preceding GUI failures

The product Main relay now confines its scripted reference teacher to a
simulated fixture session. For a real desktop request without an internally
authorized teacher or a loaded local S1 backend, it returns an unavailable
proposal without a selected action. Creating a private document or changing
sessions cannot select reference answers. Local Laya loading and promotion
remain separate acceptance work.
