# 架构评审 R4：外部前提、一期主路径与实施顺序

- 日期：2026-09-30。
- 请求：review 完整设计 v0.4；随后根据评审建议更新文档。
- 范围：完整设计 v0.4，即 R3 批准快照（SHA-256 `9da86109e3d790ca26d55cffe01279f7c0ebd504b6d99028ad40a5c86ea6438e`）。交叉核对相邻 harness-runtime 与 llm-client 源码、外部 I0 快照、本地 MediaPipe fork、macOS 15 SDK 头文件和 Laya 上游资料。

- 方法：单一评审者通读全文并逐项核对可验证的事实；同一方按建议修订。没有独立的关闭复核。
- 结论：REVISE。v0.4 的执行安全契约自洽，依赖事实核对无误；但 S1 的能力前提与 Laya 上游公布的限制冲突，一期真正要走的路径规格最薄，不建议按 v0.4 的 M0→M5 原计划开工。下列问题的修订已写入 v0.5，状态为“已修订，待独立复核”。

## 修订中代为做出的决定

以下各项在建议里是明确取舍，修订时按评审建议选定。它们改变了 v0.4 或更早确认过的口径，需要项目负责人确认：

1. **一期闭环先由云端教师模型顶替 S1 槽位**，本地 Laya 影子并行，微调达标后按决策程序晋级。这改变了“首个业务闭环包含本地 Laya S1”的原口径；S1 承担率 ≥90% 从一期门禁改为晋级之后的里程碑目标。
2. **AX 动作成为一期执行原语**，元素声明支持时优先于指针和按键。
3. **新增 cu-source 进程**，以及 source-macos、execution-core 两个 crate，crate 数由五个变为七个。
4. **一期只启用非按住原语**；预记账与 recovery-only helper 后置到按住类原语启用之前。
5. **接纳协议改为单事务**。
6. **S2 集成路线改为 M0 对照后定案**，没有明确依赖会话能力时选模型层直连。
7. **一期执行白名单为夹具与 TextEdit**；GoalSpec 冻结前用户确认一次；commit 及以上且未被目标覆盖的动作需要确认；对外发送类动作一期不执行。
8. **门禁调整**：冷启动条件、每任务 4/5、错误完成为 0。
9. **第 17–19、25 章移入扩展卷**，内容未改。
